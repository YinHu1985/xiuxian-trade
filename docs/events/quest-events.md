# 委托事件：触发→对话→选择→生成委托→完成得奖励

对话流程与小型事件一致——交替短对话铺垫，最后一两步行选择。不同之处在于：选择后会生成本地委托（Quest），玩家需完成委托才能获得最终奖励。

> `add_quest` 效果创建的委托直接为 `'active'` 状态

---

## 1. 宗门灵材搜集（arrive·宗门 30%）

**ID**: `sect_collection` · 每宗门一次

---

步 1｜portrait-right · 执事弟子

> 会长来得正好！本门正在炼制一批丹药，急需一味灵材。
> 听说贵商会路子广，想托您帮忙寻一寻。

步 2｜portrait-left · 会长

> 什么灵材？说来听听。

步 3｜portrait-right · 执事弟子

> 一批筑基期药材。若能弄到，本门愿出五百灵石收购。
> 不知会长意下如何？

步 4｜选择

> A. 「这单生意我接了」— 生成采购委托（筑基药材 → 奖励 500 灵石）
> B. 「我们主要做符篆生意，丹药这块不熟」— 无效果

## 2. 遗迹密卷（arrive·城镇 20%）

**ID**: `ruin_scroll_quest` · 每城镇一次

---

步 1｜portrait-right · 城主府幕僚

> 会长可曾探索过附近的遗迹？
> 前些日子有探险队带回半卷古修手札，剩下一半据说还在遗迹深处。

步 2｜portrait-left · 会长

> 你想让我找到另外半卷？

步 3｜portrait-right · 幕僚

> 正是。城主愿出高价收购——八百灵石，如何？
> 那手札记载的似乎是某种失传的功法。

步 4｜选择

> A. 「接下这个寻物委托」— 生成交付委托（800 灵石，目标据点自动分配）
> B. 「风险不小，得加钱」— 生成交付委托（1000 灵石，目标据点自动分配）

## 6. 遗失法宝（开局生成，每局 2-3 对）

此类事件不由触发概率控制，而是在**地图生成时**由生成器随机挑选宗门-废墟配对，生成一对事件。

### 事件对结构

```
┌─ 代码层：探索完成发放 ──────┐
│  触发: 抵达遗迹探索终点       │
│  数据: ruin.relicData         │
│  效果: 获得遗物物品 + 设 flag  │
└──────────────────────────────┘
           ↓ (玩家携带遗物到访宗门)
┌─ 事件 B：归还遗物 ──────────┐
│  trigger: arrive·宗门        │
│  条件: nodeId + itemsRequired │
│  对话: 会长说明 → 长老感激    │
│  效果: 消耗遗物 + 灵石 + 声望  │
└──────────────────────────────┘
```

> **注意**：发现遗物在引擎层代码中直接发放（无对话事件），归还遗物才是真正的 `arrive` 事件。

### 事件 B：归还遗物（template）

**ID**: `relic_{sectId}_return`

---

步 1｜portrait-right · 宗门长老

> 会长亲临，有失远迎。敢问何事劳烦大驾？

步 2｜portrait-left · 会长

> 前些日子在{废墟名}探查，发现了一件贵派古物。
> 应当是贵派遗失之物，特来奉还。

步 3｜portrait-right · 长老

> （接过法器，双手微颤）
> 这……这是我派遗失多年的{suffix}！会长大恩，本门铭记于心！

步 4｜portrait-left · 会长

> 物归原主，不必言谢。

→ 效果：消耗「{遗物名}」、灵石 +{rewardSs}、设 flag `relic_{sectId}_returned`
